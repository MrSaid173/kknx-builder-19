# util_est (бэкпорт из Linux 4.17)

Проблема: schedutil выбирает частоту по PELT (`util_avg`). Задача, которая проспала 10 мс, возвращается с уже «остывшей» загрузкой, и частота набирается заново за десятки миллисекунд. Для интерфейса и binder (короткие повторяющиеся всплески) это лишняя задержка. Ответ в этом дереве был `iowait` (грубо поднимает частоту при ожидании I/O) и `pelt16` (делает наоборот, медленнее).

Что делает: каждая задача хранит `util_est` (последняя загрузка активации и скользящее среднее по активациям, вес 1/4). Корневой `cfs_rq` держит сумму оценок поставленных в очередь задач. `cpu_util_freq_pelt()` (путь schedutil) берёт максимум из `util_avg` и этой суммы. Размещение задач (CASS) и балансировка не меняются.

Источник: коммит «sched/fair: Add util_est on top of PELT» (Patrick Bellasi, Linux 4.17), вариант 5.x: вычитание при `dequeue_task_fair` до пересчёта частоты, обновление среднего после. Отличия от апстрима: нет флага `UTIL_AVG_UNCHANGED` (среднее обновляется на каждом засыпании вне порога ~1%), нет `SCHED_FEAT` (в дереве нет `SCHED_DEBUG`), вместо этого sysctl `kernel.sched_util_est`. Учёт ведётся всегда, sysctl решает только, читает ли его schedutil, поэтому переключение на лету безопасно.

Файлы: `include/linux/sched.h`, `include/linux/sched/sysctl.h`, `kernel/sched/fair.c`, `kernel/sched/sched.h`, `kernel/sysctl.c`.

Включение: `experiments=utilest`. По умолчанию после загрузки `sched_util_est = 1`.

A/B без перепрошивки: `echo 0 > /proc/sys/kernel/sched_util_est`, прогон `kknx-test.sh ui`, затем `echo 1 ...` и снова `ui`. Смотрите p95 кадра и среднюю частоту; ожидание: p95 лучше, энергия чуть выше.

Проверено: патч ложится на файлы закреплённого коммита и снимается обратно; `fair.o`, `cpufreq_schedutil.o`, `core.o`, `sysctl.o` компилируются clang-16 без ошибок. Не проверено: загрузка и работа на устройстве.

## Результат на телефоне (Redmi 8)
Тест плавности `ui` (6 прогонов A-B-B-A-A-B): джанк 0,00-0,02% в обоих режимах, разницы нет. Холодный запуск 6 приложений: 2228 мс без и 2205 мс с (разница 1%, меньше разброса между раундами). Вывод: пользы не показал, в повседневную сборку не включать.
